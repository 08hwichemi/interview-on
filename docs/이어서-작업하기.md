## 만들려는 것

```
[교사·노트북]  명단에서 학생 고르기 → 질문 정하기
                  ↓
               면접 진행 — 질문 한 장씩, 타이머, 들으면서 평가
                  ↓  (태그 버튼 클릭 위주. 타자 최소화)
               저장 → 채점표 자동 집계 → "공개" 누름
                  ↓
[학생·폰]      로그인 → 내 피드백 리포트 읽기
```

**학생은 면접 중에 접속하지 않습니다.** 교사 노트북 하나로 면접이 진행되고 학생은 나중에 결과를 읽습니다. 그래서 실시간 전송 기능은 필요 없습니다.

## 정해진 것 (다시 논의하지 말 것)

- **생기부는 브라우저에서만 읽고 버립니다.** 서버에 원문을 올리지 않습니다
- **질문 추출은 규칙 기반**으로 시작. AI는 나중에 선택지로
- **채점표는 상세하게** — 태그 버튼 + 학생부종합전형 공통 평가요소 A~E
- **이메일을 쓰지 않습니다.** 학생=학번, 교사=이름. 계정은 관리자가 전부 만듭니다
- **비밀번호는 숫자 6자리 이상**
- 교사 화면(`teacher/`)과 학생 앱(`index.html`)은 **화면 구성이 다릅니다**

평가 입력 방식과 채점표 구성을 참고합니다. 다만 **저장소에 라이선스가 없어** 코드와 문구는 가져오지 않습니다. 구조만 보고 새로 씁니다. 채점 기준은 참고 사이트도 출처로 밝힌 건국대·경희대·연세대·중앙대·한국외대 공동연구「학생부종합전형 공통 평가요소 및 평가항목」(공개 문서)을 직접 근거로 삼습니다.

## Phase 3 에서 된 것

`teacher/` 에서 명단을 붙여넣어 계정을 만들 수 있습니다.

- 학생 / 선생님 탭. **선생님 탭은 관리자에게만 보입니다** (서버도 같은 기준으로 막습니다)
- 엑셀에서 복사한 것을 그대로 붙여넣기 (탭·쉼표 둘 다, 머리글 줄은 자동으로 건너뜀)
- 미리 보기에서 잘못된 줄을 먼저 알려주고, 문제없는 줄만 등록합니다
  - 학번이 숫자가 아닌 줄, 이름이 비거나 숫자뿐인 줄(칸이 잘린 줄), 붙여넣기 안에서 중복된 학번
- 만든 뒤 초기 비밀번호 표 → 복사하기 / 엑셀(CSV)로 내려받기
  - **이 표는 그때 한 번만 보입니다.** 서버에 저장되지 않습니다
- 아래에 이미 등록된 명단과 계정·비밀번호 변경 여부

가짜 서버를 붙여 브라우저에서 확인했습니다. 실제 계정으로는 아직 안 돌려봤으니,
관리자로 로그인해 **한 명만 먼저** 만들어 보고 그 계정으로 로그인되는지 확인해 주세요.

## 작업할 때 주의

- **로그인 규칙을 고칠 때**는 [계정-구조.md](계정-구조.md) 를 먼저 읽으세요. 아이디→내부주소 변환이 앱과 서버 **두 곳**에 있어서 한쪽만 고치면 모든 로그인이 깨집니다
- **`type="module"` 로 바꾸지 마세요.** 버튼들이 `onclick="함수명()"` 으로 부르고 있어서 전부 죽습니다
- **경로는 상대 경로로.** GitHub Pages 가 하위 경로에서 서비스하므로 절대 경로면 PWA 설치가 깨집니다
- SQL 로 계정을 직접 만들 때는 `confirmation_token` 등 토큰 컬럼을 **빈 문자열로** 채워야 합니다. `NULL` 이면 로그인이 "Database error querying schema" 로 실패합니다
