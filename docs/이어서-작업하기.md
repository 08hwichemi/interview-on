## 🚨 새 세션이 가장 먼저 알아야 할 것

### 1. **`main` 에 들어가야** 실제로 올라갑니다

GitHub Pages 가 내보내는 것은 **`main`** 입니다.
작업 branch 에만 올리면 **선생님 화면은 판이 그대로입니다.**
실제로 한 번 「버전이 안 바뀌는데?」 하고 걸렸습니다.

요즘은 세션마다 정해진 작업 branch 에 올리고 → **PR 을 만들어 → 사용자가 «올려줘» 하면
바로 합칩니다(merge).** 합친 PR 의 branch 는 다시 쓰지 말고, 새 일은 최신 `main` 에서
branch 를 새로 땁니다.

```bash
git fetch origin -q && git show origin/main:version.txt   # 올라갔는지 확인
```

### 1-1. 합치기 전에 선생님이 보시게 하려면 — 미리보기 주소

GitHub Pages 는 main 만 내보내지만, branch 파일을 그대로 보여 주는 길이 있습니다(2026-10-05 부터 씀):

```
https://raw.githack.com/08hwichemi/interview-on/<branch>/teacher/index.html
```

같은 Supabase 라 로그인·명단이 그대로입니다(실제 서버에 기록되니 보기만 하시라고 말씀드립니다).
⚠️ 브라우저가 옛 파일을 기억하므로 **고칠 때마다 판 번호를 올리고**(`판올리기.py`), 선생님께는
**Ctrl+F5** 를 부탁드립니다. 이 작업 환경에서는 raw.githack 이 막혀 있어 직접 열어 볼 수 없습니다
(`raw.githubusercontent.com` 은 열려서 파일이 올라갔는지는 거기서 확인합니다).

### 2. 판 번호는 손으로 고치지 마세요

셋 중 하나라도 어긋나면 「새로고침」을 눌러도 띠가 안 사라집니다.

`tools/화면-시험/` 에 검사가 들어 있습니다. [그 폴더의 README](../tools/화면-시험/README.md) 를 보세요.

### 5. Supabase 무료 요금제 — 요청과 로그를 아낍니다

**서버 요청 1건 = 로그 1줄**이라 학생 수만큼 곱해지는 주기 확인은 금방 한도를 먹습니다.
**톡만 실시간**이고 나머지 뱃지는 앱을 열 때·돌아올 때만 확인합니다.
새 «다시 확인» 은 `config.js` 의 `throttleRefresh()` 로 감싸세요.
**로그를 조회(`query_logs`)하는 것도 사용량(Log Query)에 잡힙니다** — 먼저 묻고, 기간을 좁게.
원인을 볼 때는 로그 대신 `pg_stat_statements`(`execute_sql`)를 먼저 읽으세요 — 사용량에 안 잡힙니다.
무료 한도(두 방 합산, 한 달): Logs Ingest 5GB · Logs Query 1,000GB · Egress 5GB.
자세한 것은 [할-일.md](할-일.md) 의 «Supabase 로그 줄이기».
