## 만들려는 것

```
[교사·노트북]  명단에서 학생 고르기 → 질문 정하기
                  ↓
               면접 진행 — 질문 한 장씩, 타이머, 들으면서 평가
                  ↓  (태그 버튼 클릭 위주. 타자 최소화)
               채점표 → «면접 끝내기» → 확인 → «학생에게 전달»
                  ↓
[학생·폰]      로그인 → 내 피드백 리포트 읽기
```

**학생은 면접 중에 접속하지 않습니다.** 교사 노트북 하나로 면접이 진행되고 학생은 나중에 읽습니다.

**타학교 면접**(2026-10-11~): 다른 학교 학생은 명단 · 계정 없이 이름 · 희망 전공만 적고 같은 화면으로 면접합니다.
평가서는 QR(`r.html#열쇠`)로 하루만 열리고 서버가 지웁니다. 자세한 것은 [할-일.md](할-일.md) 의 «🏫 타학교 면접».
(학생 폰을 켜 두고 녹음하는 아이디어는 [할-일.md](할-일.md) 의 «아이디어 보관함» 에 있습니다)

## 정해진 것 (다시 논의하지 말 것)

- **생기부는 브라우저에서만 읽고 버립니다.** 서버에 원문을 올리지 않습니다
- **질문 추출은 규칙 기반**으로 시작. AI 는 나중에 선택지로
- **이메일을 쓰지 않습니다.** 학생=학번, 교사=이름. 계정은 관리자가 전부 만듭니다
- **계정을 만들고·되돌리고·지우는 일은 관리자만** 합니다. 교사 화면에는 그 길이 없습니다
- **초기 비밀번호는 몫마다 하나씩** — 학생 `111111`, 선생님 `123456`. 첫 로그인 때 반드시 바꿉니다
- **채점표는 공통 평가요소 + 면접 태도 + 기록 확인** 을 한 표에
- 화면은 **왼쪽 목록 : 오른쪽 내용 = 2 : 8**
- **수시 지원 자료는 서버끼리만 주고받습니다.** 저쪽 방 열쇠를 브라우저에 넣지 않습니다
  (자세한 것은 [할-일.md](할-일.md) 의 「수시 자료는 어떻게 오는가」)

## 🚨 새 세션이 가장 먼저 알아야 할 것

### 1. **`main` 에 들어가야** 실제로 올라갑니다

GitHub Pages 가 내보내는 것은 **`main`** 입니다.
작업 branch 에만 올리면 **선생님 화면은 판이 그대로입니다.**
실제로 한 번 「버전이 안 바뀌는데?」 하고 걸렸습니다.

요즘은 세션마다 정해진 작업 branch 에 올리고 → **PR 을 만들어 → 사용자가 «올려줘» 하면
바로 합칩니다(merge).** 합친 PR 의 branch 는 다시 쓰지 말고, 새 일은 최신 `main` 에서
branch 를 새로 땁니다.

```bash
git fetch origin -q && git show origin/main:version.txt   # 올라갔는지 확인
```

### 1-1. 합치기 전에 선생님이 보시게 하려면 — 미리보기 주소

GitHub Pages 는 main 만 내보내지만, branch 파일을 그대로 보여 주는 길이 있습니다(2026-10-05 부터 씀):

```
https://raw.githack.com/08hwichemi/interview-on/<branch>/teacher/index.html
```

같은 Supabase 라 로그인·명단이 그대로입니다(실제 서버에 기록되니 보기만 하시라고 말씀드립니다).
⚠️ 브라우저가 옛 파일을 기억하므로 **고칠 때마다 판 번호를 올리고**(`판올리기.py`), 선생님께는
**Ctrl+F5** 를 부탁드립니다. 🚨 **그래도 옛 판이 오는 일이 잦습니다** — raw.githack 이 화면 파일(index.html)
자체를 한동안 쥐고 있어서, 판 번호를 올려도 옛 화면 + 옛 코드를 그대로 줍니다(2026-10-10 영역 표가 맨모양으로
보인 것, 10-11 스크롤이 안 되는 것처럼 보인 것 — 둘 다 이것). 주소 뒤에 `?p=3` 을 붙이는 것도 **안 통할 때가 있습니다**
(10-11 저녁, 11.5 를 올리고 한참 뒤에도 11.3 이 옴). 선생님께 «판 번호가 몇으로 보이세요?» 를 먼저 여쭙는 게 가장 빠릅니다.

**확실한 길 — 커밋 번호로 여는 주소**(2026-10-11 부터 이걸로):
```
https://rawcdn.githack.com/08hwichemi/interview-on/<커밋 번호 전체>/teacher/index.html
```
커밋 번호(`git rev-parse HEAD`)가 든 주소는 내용이 절대 안 바뀌니 쥐고 있어도 늘 그 판입니다. 올릴 때마다 주소가 새로
생기는 것뿐이니, 선생님께는 **올릴 때마다 새 주소**를 드립니다. (branch 이름 주소는 «대충 최신» 일 뿐입니다) 이 작업 환경에서는 raw.githack 이 막혀 있어 직접 열어 볼 수 없습니다
(`raw.githubusercontent.com` 은 열려서 파일이 올라갔는지는 거기서 확인합니다).

### 5. Supabase 무료 요금제 — 요청과 로그를 아낍니다

**서버 요청 1건 = 로그 1줄**이라 학생 수만큼 곱해지는 주기 확인은 금방 한도를 먹습니다.
**톡만 실시간**이고 나머지 뱃지는 앱을 열 때·돌아올 때만 확인합니다.
새 «다시 확인» 은 `config.js` 의 `throttleRefresh()` 로 감싸세요.
**로그를 조회(`query_logs`)하는 것도 사용량(Log Query)에 잡힙니다** — 먼저 묻고, 기간을 좁게.
원인을 볼 때는 로그 대신 `pg_stat_statements`(`execute_sql`)를 먼저 읽으세요 — 사용량에 안 잡힙니다.
무료 한도(두 방 합산, 한 달): Logs Ingest 5GB · Logs Query 1,000GB · Egress 5GB.
자세한 것은 [할-일.md](할-일.md) 의 «Supabase 로그 줄이기».

### 5-1. 선생님 화면을 고치면 «따라 하기» 도 같이 고칩니다

설명서는 글이 아니라 **실제 면접 화면 위에서 도는 시뮬레이션**입니다(`?guide` → 가짜 서버 `assets/js/guide-server.js` +
안내 `assets/js/guide-coach.js`). 걸음마다 **화면의 id · 단추를 직접 가리키므로**, 단추 이름 · id · 순서를 바꾸면
따라 하기가 엉뚱한 곳을 가리키거나 멈춥니다.

- 고친 뒤 **`check-guide.js`** 를 꼭 돌리세요(노트북 · 휴대폰 크기로 여섯 장을 끝까지 눌러 봄)
- 새 기능을 넣으면 따라 하기에도 걸음을 더할지 생각합니다(PR #30 은 ▲ ▼ · 꼬리 질문 걸음을 더함).
  누른 결과가 화면의 다른 곳에 생기면 그 걸음에 `show` 를 붙여 결과를 보여 줍니다
- 앱이 새 표 · 새 거르기(`.gt` 등)를 쓰면 `guide-server.js` 에도 더해야 따라 하기가 안 깨집니다
- 🚨 따라 하기는 **세 번 고쳐 지금 모양**이 됐습니다(선생님 말씀: «다음 단추 말고 실제 단추» → «직접 입력이 아니라 미리 내용이 있는 시뮬레이션, 마이크도 예시로»
  → «따라하기 하나로 충분»). 자세한 까닭은 [할-일.md](할-일.md) PR #29 항목
