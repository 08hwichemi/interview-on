      - **학년·분류 칩은 «필터» 입니다 — 열쇠가 아닙니다.** 처음엔 정확히 같은

        제약을 한 번에 바꾸면 그 줄이 걸립니다 — 잠깐 두 값을 다 허락하는 임시
        제약으로 바꾼 뒤 데이터를 옮기고, 그다음 최종 제약으로 좁혔습니다.
      - 학생 앱 홈에 새 메뉴 → **작성 / 조회** 두 탭(둘 다 남겨 뒀습니다. 조회가
        따로 있는 게 나은 지점이 있다고 하셔서).
        - **작성**: 위 필터로 «내가 쓴 것 전체 목록» 을 좁혀 보고, 카드가 이미
          펼쳐진 입력칸이라 바로 고칠 수 있습니다. **「＋ 새 질문 쓰기」를 누르면
          작은 창(모달)이 떠서 그때 한 번만 학년·분류를 정합니다** — 그 뒤로는
          목록에서 뱃지로 구분됩니다. 저장 버튼 없이 자동저장 — 쓰는 동안은 그 기기 브라우저에
          임시본만, 서버에는 칸을 벗어날 때 · 앱을 떠날 때 · 계속 쓰면 2분마다
          (2026-09-30, 예전엔 멈추고 1.5초). 둘 다 비면 그 줄은 지웁니다.
        - **조회**: 같은 필터로 읽기 전용 카드를 봅니다. 카드마다 **«수정» 단추**가
          있어 누르면 작성 탭으로 넘어가 그 학년·분류로 필터가 자동으로 맞춰지고
          그 카드가 잠깐 반짝이며 스크롤됩니다(`practiceJumpToEdit`).
      - **학생이 만든 분류**는 옆의 «✎» 로 이름을 바꾸거나 지웁니다(모달 안에서
        「＋ 새 분류」로도 바로 만들 수 있습니다). 이름을 바꾸면 그 분류로 이미
        써 둔 답안들도 새 이름을 따라갑니다. **그 분류로 쓴 답안이 있으면
        못 지웁니다**(먼저 답안을 지우거나 옮기라고 안내).
      - **선생님 코멘트** — 답안마다 여러 개가 시간순으로 쌓입니다(대화 아님,
        선생님만 씁니다·일방향). 학생은 조회 탭에서 읽기만 하고, 열어 보면

        연습장」 보다가 학생을 계속 바꿔야 할 때 매번 다시 누르지 않아도 됩니다.

           다른 활동이 아예 안 보였습니다. 질문에 `order` 번호가 붙고 화면(`sgRanked`)은 그 번호대로
         - **자리말에 활동 이름**: 창체 한 묶음에 활동이 여럿이면 「진로활동 **프로젝트 큐리어톤**에서 「…」을
           탐구했다고」 처럼 어느 활동인지 질문에 적습니다(`sgPlaceOf` 셋째 인자). 이름을 못 지은 이야기는 뺍니다
         - 🚨 같이 고친 것: **날짜의 점**(「큐리어톤(2026.05.26.~2026.07.14.)」)에서 문장이 끊겨 이야깃거리가
           「)에 참여해 호기심에서출발한 질문」 이 됐습니다 → 숫자 뒤 점은 숨기고 나눕니다(`sgShieldDots`).
           괄호 뒤부터 잘린 토막·괄호 안 맞는 것·「…질문」「…결과」 같은 뭉뚱그린 말은 버립니다(`sgLooksJunk`)
         - 창체에서는 탐구·발표 낱말이 진로보다 먼저 — 진로활동 안의 탐구가 전부 «진로와 관련된 활동» 으로
           묻히던 것
         - **PR #14 위에 얹은 것(2026-10-05 밤, 판 2026-10-05.7~.8, branch `claude/confident-mccarthy-bdbjwk`):**
           위의 «화면에서 빼고 안쪽에서만» 과, 같은 진로활동 기록에서 「…을 토론하며」 가 «주제로 발표했다고»

           「…무엇일까?를 핵심 질문으로 설정」 이라고 적혀도 물음으로 잡는 것. PR #14 가 먼저 합쳐지면 이

         - ⚠️ **이야깃거리는 여전히 문장 하나하나에서 찾습니다.** 이야기는 «어느 활동에서 나왔는지» 를 알고

      2. [x] **질문 수준** — 틀 8개 → **12가지 생김새 × 틀 42개** (`SG_FRAMES`). 기출 질문 2,360줄을
         읽고 그 말투(「…했다고 기록되어 있습니다. ~을 설명하고, ~도 말해 주세요」 — 본 질문 + 꼬리
         질문 한 줄)를 따랐습니다.
         - 생김새는 문장의 낱말로 정합니다(`sgShapeOf`): 실험·측정 → **실험** / 발표·보고서·카드뉴스 →
           **발표** / 회장·모둠·협력 → **역할** / 진로활동·직업 → **진로** / 「…할까?」 → **물음** /

## 아이디어 보관함

### 학생 폰에 면접 시간 띄우기 ★ 먼저 해 볼 것

> 학생이 면접 전에 휴대폰으로 로그인해 두고, 교사가 진행 화면에서 «면접 시작» 을
> 누르면 학생 휴대폰에 시간이 뜨는 것. 학생도 시간을 보면서 면접을 봅니다.
> 화면에는 **면접 전체 시간을 크게, 질문별 답변 시간을 그보다 작게** 둘 다.

**됩니다.** 아래 녹음보다 훨씬 쉽습니다. 정해야 할 것(저장 용량·동의·삭제)이 없고,
보내는 것이 숫자 두 개뿐이라 먼저 해 볼 만합니다.

**모자란 조각은 하나뿐입니다 — 지금 시간이 서버에 안 올라갑니다.**
교사 화면의 시계(`teacher-app.js` 의 `tickId`)는 브라우저 안에서만 돕니다.
`interviews` 에 흐르는 시간을 적어 두면 학생 폰이 그걸 읽습니다.

```sql
alter table public.interviews
  add column if not exists running_since  timestamptz,  -- 시계가 돈 순간 (멈추면 null)
  add column if not exists elapsed_seconds int not null default 0,  -- 멈출 때까지 쌓인 초
  add column if not exists current_seq     int;         -- 지금 몇 번 질문인지
```

- **초를 그대로 보내지 않습니다.** 1초마다 서버에 쓰면 낭비입니다.
  «언제부터 돌기 시작했는지» 만 적어 두고, 학생 폰이 지금 시각에서 빼서 셉니다.
  시작·일시정지·질문 넘김, 이 세 번만 서버에 씁니다
- 학생 폰은 **Realtime**(`postgres_changes`) 으로 받거나, 안 켜면 5초마다 물어봅니다
- 학생은 `status='진행중'` 인 자기 면접을 읽을 수 있어야 합니다.
  지금 RLS 는 `'전달됨'` 만 내려주므로 **정책을 하나 더 만들어야 합니다**
  (진행중일 때는 시간 관련 칸만 보이게)
- 학생 화면은 홈에 뜨는 띠 하나면 됩니다 — 「지금 면접 중입니다」 + 시간 두 개.
  질문 글자는 **보내지 않습니다.** 미리 보이면 면접이 아닙니다

**걸림돌**

- 학생 폰 화면이 꺼집니다 → `navigator.wakeLock` 으로 붙잡습니다 (아이폰 16.4+)
- 교사 브라우저가 꺼지면 `running_since` 가 켜진 채 남습니다 →
  면접을 이어서 열 때 정리합니다 (아래 «이어서 하기» 와 같이 다룹니다)

### 학생 폰 연동 — 면접 중 녹음

> 교사가 학생 면접을 시작하면, 학생이 휴대폰을 켜 두었을 때 화면에 면접 시간이 뜨고
> 그 자리에서 녹음이 되게 하는 것.

**됩니다.** 필요한 조각이 이미 거의 다 있습니다.

- 학생 앱에 **녹음 기능이 이미 있습니다** (`assets/js/interview.js` 의 `MediaRecorder`)
- 면접이 시작되면 `interviews` 에 `status='진행중'` 인 줄이 생깁니다.
  학생 폰은 자기 면접이 진행중인지 알 수 있습니다
- 실시간으로 띄우려면 Supabase **Realtime**(`postgres_changes`) 을 켜면 됩니다.
  안 켜면 몇 초마다 물어보는 방식으로도 됩니다

**먼저 정해야 할 것**

- 녹음 파일을 **어디에 둘지** — Supabase Storage. 용량과 보관 기간을 정해야 합니다
  (한 명 10분이면 대략 5~10MB. 전교생 192명이면 1~2GB)
- **누가 들을 수 있는지** — 본인만? 면접한 선생님도?
- **언제 지울지** — 학년 끝나면 자동 삭제할지
- **동의** — 목소리는 개인정보입니다. 학생이 켤지 말지 고르게 해야 합니다

**걸림돌 (학생 앱에 이미 겪어서 경고 문구가 붙어 있는 것들)**

- 화면이 꺼지면 녹음이 끊깁니다
- 다른 앱으로 나가면 마이크가 끊길 수 있습니다
- 아이폰은 특히 까다롭습니다

    그러면 그 뒤로 사람이 아무리 만져도 «이미 찼다» 며 진짜 걸음을 한 번도 안 쌓아,
    뒤로가기가 늘 그냥 나가 버립니다. 증상: **걸음은 1칸인데 히스토리만 늘어남**
  - 🚨 **`pointerdown` 과 `touchstart` 를 둘 다 듣지 마세요.** 손가락 한 번에 두
    이벤트가 와서 걸음을 두 칸 쌓는데 크롬이 인정하는 것은 한 칸뿐입니다.
    나머지는 허깨비인데 개수만 늘어, **네 칸인 줄 알았던 여유분이 실제로는 두 칸**
    이었습니다. 자취에 「걸음+1」이 같은 초에 네 줄 찍힌 것이 증거입니다.
    자판 꾹 누름도 있으니 250ms 안에는 거듭 쌓지 않습니다
  - 🚨 **뒤로가기를 처리하는 «중» 에는 걸음을 쌓지 마세요.** 그 순간은 사람의 손이
    닿은 때가 아니라 크롬이 건너뜁니다. 막지도 못하면서 히스토리만 늘립니다 —
    「걸음 1칸인데 히스토리만 늘어난다」가 바로 그것이었습니다
  - 🚨 **여유분을 넉넉히 쌓아 둡니다** (`GUARD_TARGET`, 지금 4칸).
    한 칸만 두었더니 «다른 화면 → 홈» 뒤로가기 한 번에 0칸이 되고,
    사람이 화면을 만지기 전에 또 누르면 채울 틈이 없어 그대로 꺼졌습니다.
    **실제 휴대폰 자취로 확인한 대목입니다** — 그 두 번째 누름에는

    **믿을 것은 여유분 칸수입니다**
  - 일부러 나가는 길(로그아웃·새 판 새로고침·교사/관리자 화면으로 이동)에서는
    `allowLeaving()` 을 먼저 불러야 «나가시겠습니까?» 가 안 뜹니다
  - 안내는 토스트가 아니라 **«앱을 종료할까요?» 물음창**입니다.
    토스트는 눈에 안 띄고, «한 번 더» 의 두 번째 누름이 건너뛰기에 걸립니다
