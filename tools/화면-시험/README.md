# 화면 시험 (브라우저로 직접 눌러 보는 검사)

서버 없이, **가짜 Supabase**(`stub4.js` · `stub5.js`)를 끼워 넣고 진짜 브라우저로
화면을 눌러 봅니다. 사람이 눈으로 하던 확인을 그대로 옮긴 것이라
「400px 에서 옆으로 넘치는가」 「단추 글자가 바뀌는가」 같은 것까지 봅니다.

## 돌리는 법

```bash
# 1) 저장소 맨 위에서 간이 서버를 켭니다
cd <저장소>
python3 -m http.server 8777 &

# 2) 검사를 돌립니다 (Playwright + 미리 깔린 크로뮴)
cd tools/화면-시험
NODE_PATH=/opt/node22/lib/node_modules /opt/node22/bin/node check-susi.js
```

끝에 `✅ 모두 통과` 또는 `❌ N개 실패` 가 찍힙니다.
크로뮴 자리는 각 파일 맨 아래의 `executablePath` 에 적혀 있습니다
(`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`). 자리가 다르면 그 줄만 고치세요.

`shot-susi.js` · `shot-setup.js` 는 검사가 아니라 **화면을 사진으로 찍는** 것입니다
(`setup-1100.png` 처럼 옆에 떨어집니다). 모양을 눈으로 볼 때 씁니다.

## 왜 여기에 있는지

전에는 이 파일들이 작업용 임시 폴더에만 있었습니다.
**대화창을 새로 열면 그 폴더가 사라져** 매번 처음부터 다시 만들었습니다.
그래서 지금도 통과하는 것만 저장소로 옮겼습니다.

옮기지 않은 것이 서른 개쯤 더 있었습니다. 대부분 그때그때 보려고 만든
«화면 상태를 찍어 보는» 쪽지라 통과/실패가 없고, 몇몇은 **그 뒤에 일부러 바꾼 것**을
옛 모습으로 알고 있어 이제 맞지 않습니다 (뒤로가기 걸음 세는 방식, 진단 창을
꾹 누르기에서 세 번 두드리기로 바꾼 것 등). 필요하면 그때 새로 만드는 편이 빠릅니다.

## 고칠 때

화면을 고쳤는데 검사가 빨갛게 되면, **먼저 검사가 낡은 것인지 화면이 깨진 것인지**
가리세요. `git stash` 로 고친 것을 잠깐 치우고 다시 돌려 보면 압니다 —
치웠는데도 똑같이 실패하면 그 검사가 낡은 것입니다.
